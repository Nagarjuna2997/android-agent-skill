01 / THE TOOLBOX

A platform layer.
From source to screen.

One shared execution core, available through the command line and MCP. Clear boundaries between source analysis and observed runtime behavior.

01

Understand the project

Inspect Gradle modules, version catalogs, manifests, permissions and Kotlin/Java source signals.

android-agent inspect
02

Build. Test. Diagnose.

Run trusted Gradle wrappers. Preserve exit status, fresh reports and artifact hashes. Extract crash signals from logs.

android-agent test unit
03

Control the device

Select an authorized device. Launch apps, inspect the hierarchy, tap unique elements and capture the result.

android-agent ui inspect
04

Review the integration

Find Firebase rule risks, permission declarations and Compose review signals. Every heuristic states its limits.

android-agent firebase audit
05

Prepare for release

Review form-factor-aware target SDK requirements. Compose supplied screenshots with configurable local templates.

android-agent play validate
06

Keep the evidence

Save deterministic workflows, source fingerprints and hashed results. Resume only when the context still matches.

android-agent runs resume

04 / AGENT INTERFACE

The same tools.
Inside your agent.

Launch a project-scoped stdio MCP server. Mutation tools are disabled by default. Enable them deliberately; destructive actions keep a separate confirmation boundary.

SDK protocol tests included. Individual agent-client integrations are not yet certified.

  "mcpServers": {

      "command": "android-agent",
      "args": [
        "--project", "/absolute/path/to/app",
        "mcp"
      ]
    }
  }

EMULATOR & UI

Select. Observe. Act.

AVD creation uses installed system images. Launch and boot verification are separate. UI actions prefer hierarchy text and resource IDs over image guesses.

KOTLIN & COMPOSE

Signals worth reviewing.

Find blocking calls, unstructured scopes and localization concerns. Static matching is not compiler analysis or a recomposition measurement.

FIREBASE & PLAY

Know what needs a closer look.

Review source rules and configuration paths locally. Play thresholds are dated and form-factor-aware. No deployed-security or store-approval claims.

SCREENSHOT STUDIO

Make the capture useful.

Stack, split and minimal templates. Your captions, colors and localized captures. Opaque exports and asset hashes; review the final composition before upload.

05 / BUILT AROUND TRUST

Local by default.
Explicit by design.

No silent uploads.

Gemini, OpenAI and Claude adapters require opt-in before receiving project context. Loopback models stay local. Fallback is configurable, and model suggestions never execute automatically.

Evidence has limits.

Fixture benchmarks are included. No WITH/WITHOUT agent-performance score is claimed. Real-device verification, semantic analysis and broader release checks remain on the roadmap.
