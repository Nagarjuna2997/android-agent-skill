# App startup and Baseline Profiles

Faster cold start with the App Startup library for ordered, lazy initialization and Baseline Profiles generated by a `baselineprofile` module with Macrobenchmark 1.5.0: initializers replacing `ContentProvider` hacks, the Baseline Profile Gradle plugin, a profile generator that drives the critical user journey, a startup benchmark that proves the gain, and the release packaging that ships the profile.

## When to use

- Any app going to production. Baseline Profiles typically cut cold start and first-frame jank measurably by pre-compiling the hot path; Compose itself ships one, and the app's own screens benefit from another.
- App Startup replaces third-party libraries' auto-init content providers and your own `Application.onCreate` sprawl with declared dependencies; it matters most when several SDKs initialize at launch.
- Benchmarks need a physical device or an emulator with a Play-less image; results from an emulator are directional only.

## Dependencies

Startup and the profile installer are not in `data/versions.json`; Benchmark/Macrobenchmark is (1.5.0).


## Manifest and permissions

App Startup registers its provider through the library manifest. To remove an SDK's auto-initializer and run it through your own `Initializer`:

```xml
<provider
    android:name="androidx.startup.InitializationProvider"
    android:authorities="${applicationId}.androidx-startup"
    android:exported="false"
    tools:node="merge">
    <meta-data android:name="com.example.app.startup.LoggingInitializer" android:value="androidx.startup" />
    <!-- Remove a library's own initializer so it runs lazily instead -->
    <meta-data android:name="androidx.work.WorkManagerInitializer" android:value="androidx.startup" tools:node="remove" />
</provider>
```

No runtime permissions. The benchmark module's manifest needs nothing beyond what the wizard generates.

## Implementation

### Initializers

```kotlin
package com.example.app.startup

import android.content.Context
import androidx.startup.AppInitializer
import androidx.startup.Initializer
import com.example.app.BuildConfig
import timber.log.Timber

class LoggingInitializer : Initializer<Unit> {
    override fun create(context: Context) {
        if (BuildConfig.DEBUG) Timber.plant(Timber.DebugTree())
    }
    override fun dependencies(): List<Class<out Initializer<*>>> = emptyList()
}

/** Not declared in the manifest: run on demand from the first screen that needs analytics. */
class AnalyticsInitializer : Initializer<AnalyticsClient> {
    override fun create(context: Context): AnalyticsClient = AnalyticsClient.create(context)
    override fun dependencies() = listOf(LoggingInitializer::class.java)
}

fun Context.analytics(): AnalyticsClient =
    AppInitializer.getInstance(this).initializeComponent(AnalyticsInitializer::class.java)
```

Only initializers listed in the manifest run at process start; others run lazily and once when `initializeComponent` is first called. Keep `create` synchronous and short; anything slow goes to a coroutine on an application scope after the first frame.

### Deferred work after first frame

```kotlin
@HiltAndroidApp
class App : Application() {
    @Inject @ApplicationScope lateinit var scope: CoroutineScope
    @Inject lateinit var syncScheduler: SyncScheduler

    override fun onCreate() {
        super.onCreate()
        Channels.create(this)
        // Defer non-critical work past the first frame; it does not block the launcher.
        scope.launch { syncScheduler.schedulePeriodic() }
    }
}
```

### Baseline Profile generator

`baselineprofile/src/main/java/.../BaselineProfileGenerator.kt`:

```kotlin
package com.example.app.baselineprofile

import androidx.benchmark.macro.junit4.BaselineProfileRule
import androidx.test.ext.junit.runners.AndroidJUnit4
import androidx.test.uiautomator.By
import androidx.test.uiautomator.Until
import org.junit.Rule
import org.junit.Test
import org.junit.runner.RunWith

@RunWith(AndroidJUnit4::class)
class BaselineProfileGenerator {
    @get:Rule val rule = BaselineProfileRule()

    @Test fun generate() = rule.collect(
        packageName = "com.example.app",
        includeInStartupProfile = true,
        maxIterations = 15,
    ) {
        pressHome()
        startActivityAndWait()
        // Critical user journey: open the list, scroll, open a detail.
        device.wait(Until.hasObject(By.res("note_list")), 5_000)
        val list = device.findObject(By.res("note_list"))
        list?.fling(androidx.test.uiautomator.Direction.DOWN)
        device.findObject(By.res("note_item"))?.click()
        device.wait(Until.hasObject(By.res("note_detail")), 5_000)
    }
}
```

Expose resource ids from Compose with `Modifier.semantics { testTagsAsResourceId = true }` on the root and `Modifier.testTag("note_list")` on the nodes.

### Startup benchmark

```kotlin
@RunWith(AndroidJUnit4::class)
class StartupBenchmark {
    @get:Rule val rule = MacrobenchmarkRule()

    @Test fun startupNoCompilation() = startup(CompilationMode.None())
    @Test fun startupBaselineProfile() = startup(CompilationMode.Partial(BaselineProfileMode.Require))

    private fun startup(mode: CompilationMode) = rule.measureRepeated(
        packageName = "com.example.app",
        metrics = listOf(StartupTimingMetric()),
        compilationMode = mode,
        startupMode = StartupMode.COLD,
        iterations = 10,
    ) {
        pressHome()
        startActivityAndWait()
    }
}
```

## Verify

```sh
./gradlew :app:generateReleaseBaselineProfile          # device connected; writes app/src/release/generated/baselineProfiles/*.txt
ls app/src/release/generated/baselineProfiles/          # baseline-prof.txt and startup-prof.txt
./gradlew :app:assembleRelease
unzip -l app/build/outputs/apk/release/app-release.apk | grep -E "assets/dexopt/baseline.prof"   # profile packaged
./gradlew :baselineprofile:connectedBenchmarkReleaseAndroidTest   # StartupBenchmark; compare timeToInitialDisplay
adb shell dumpsys package dexopt | grep -A2 com.example.app     # after install + a few seconds: status=speed-profile
```

Compare `timeToInitialDisplayMs` median between `None` and `Partial`; a working profile shows a clear reduction (often 20 to 40 percent on cold start). Report the two medians, the device and whether it was an emulator. The profile is verified by `ProfileVerifier.getCompilationStatusAsync()` from `profileinstaller` if you want a runtime check in a debug screen.

Commit the generated `baseline-prof.txt`; regenerate when the critical journey or major dependencies change.

## Pitfalls

- Baseline Profiles are generated from a release (minified) build; running the generator against debug produces a profile that does not match release class names.
- An emulator with Google Play cannot be rooted and the generator needs root or a userdebug image; use a Gradle-managed device with the `aosp` image or a physical device.
- Profiles are installed by `profileinstaller` on first launch and compiled by the system during idle; a benchmark immediately after install can show no gain. `CompilationMode.Partial(Require)` forces it for measurement.
- Heavy work in `Initializer.create` moves the cost, it does not remove it. Defer, do not just reorder.
- Removing a library initializer (`tools:node="remove"`) means you must initialize it yourself before first use; WorkManager with a custom factory is the common case.
- The Startup Profile (`includeInStartupProfile = true`) optimizes dex layout and needs R8 and AGP support; it is picked up automatically when present.
- Benchmark numbers from a laptop emulator are not comparable across runs; record the device model.
